1. Bibliography and citations

A bibliography is more than a list placed at the end of a document.

A bibliographic workflow normally involves several distinct operations:

  • recording information about books, articles, editions, translations, chapters, and other sources;
  • identifying each record with a stable key;
  • citing selected records in the running text, in notes, or in other parts of the document;
  • deciding which records belong in a bibliography;
  • sorting and grouping those records;
  • formatting citations and bibliography entries according to a bibliographic style;
  • placing one or more bibliography lists in the document.

ConTeXt MkIV and LMTX integrate these operations into the core bibliography subsystem. ConTeXt can read structured bibliographic data, produce many forms of citation, format complete bibliographic entries, and assemble local or global bibliography lists.

The same bibliographic record can therefore be used in several ways. It may appear as:

  • a short author–date citation in the text;
  • a numerical citation;
  • an author–page reference;
  • a full or shortened reference in a note;
  • a complete entry in a bibliography;
  • an item in one of several specialised bibliography lists.

This page introduces the organisation of the bibliography subsystem and provides a route through four practical guides.

2. The central distinction: data and presentation

Bibliographic data and bibliographic formatting are separate.

A bibliographic record may contain information such as: 

author
title
editor
translator
publisher
year
volume
pages
doi

These data describe a publication. They do not by themselves determine how the publication will appear in a citation or in a bibliography.

The same record can be formatted according to different conventions:

  • an author–date style;
  • a notes-and-bibliography style;
  • an author–page style;
  • a numerical style;
  • a publisher's or project's own house style.

This separation allows a project to change its citation and bibliography style without rewriting the underlying bibliographic records.

2.1. A typical workflow

A common workflow uses a bibliography manager such as JabRef to create and maintain a .bib database. JabRef is mentioned here as one possible bibliography manager, but the .bib file may equally well be edited with Emacs or any other suitable text editor, provided that it is saved using UTF-8 encoding.

The data are then loaded and processed directly by ConTeXt: 

JabRef or another bibliography manager
                 |
                 v
        bibliographic data
           references.bib
                 |
                 v
          ConTeXt dataset
                 |
                 v
   bibliographic specification
                 |
                 v
       citations and lists

JabRef manages the records. ConTeXt determines how they are selected, cited, sorted, and typeset.

ConTeXt reads .bib files directly. It does not require the external BibTeX program and does not normally produce an intermediate .bbl file.

3. The main elements of the ConTeXt bibliography system

Several terms recur throughout the guides. Their functions should not be confused.

Element Function
Bibliographic source A file, buffer, Lua table, XML document, or other source containing 
 bibliographic records.
Dataset A named collection into which ConTeXt loads bibliographic records.
Record key The unique identifier used to retrieve a record from a dataset.
Specification The rules governing the formatting of citations and bibliography entries.
Rendering A named configuration for producing a particular bibliography list.
method The rule determining which records are selected for a list.
sorttype The rule determining the order of the selected records.
Citation command A command such as \cite that retrieves and presents a record.
Placement command A command such as \placelistofpublications that inserts a 
 bibliography list into the document.

A useful simplified model is: 

bibliographic source
        |
        v
     dataset
        |
        +----------> citation
        |
        v
 specification + rendering
        |
        v
 bibliography list

4. A first look

The following example shows the main operations without explaining all their details: 

\usebtxdataset[main][references.bib]
\setupbtx[dataset=main]

\usebtxdefinitions[apa]

\definebtxrendering
  [mainlist]
  [apa]
  [dataset=main,
   sorttype=authoryear]

\starttext

A bibliographic record can be cited in the text
\cite[authoryear][beiser1987].

\subject{Bibliography}

\placelistofpublications
  [mainlist]
  [method=global]

\stoptext

This example performs five operations:

  1. it loads records from references.bib into a dataset;
  2. it selects that dataset as the default one;
  3. it loads a bibliographic specification;
  4. it defines a bibliography rendering;
  5. it places the records cited in the document.

The commands are introduced progressively in the guides. Readers who simply want to create their first citation and bibliography should begin with Guide 1.

The guides form a progression.

They begin with a small, self-contained document and gradually move toward multiple bibliographies, editorial environments, and book-length projects.

5.1. Guide 1 — Creating a bibliography and citing sources

Page: Creating a bibliography and citing sources

This guide is the recommended starting point.

It shows how to:

  • create and maintain bibliographic records in a .bib file;
  • understand categories, fields, names, and record keys;
  • load the records into ConTeXt;
  • cite a book or article in the running text;
  • print a bibliography containing the cited records;
  • place bibliographic data in a buffer for a self-contained example;
  • recognise the most common causes of unresolved citations.

The guide uses a small selection of real-world records resembling those found in a scholarly bibliography maintained with JabRef.

Start here if:

  • you have never used the ConTeXt bibliography subsystem;
  • you already have a .bib file but do not know how to load it;
  • you want a minimal working example;
  • your citations are not resolving;
  • you want to understand the relation between JabRef, a .bib database, and ConTeXt.

5.2. Guide 2 — Understanding datasets, styles, renderings, selection, and sorting

Page: Understanding bibliography datasets, styles, renderings, selection, and sorting

This guide explains the conceptual organisation of the bibliography subsystem.

It shows how to:

  • distinguish a bibliographic file from a dataset;
  • choose or name the default dataset;
  • understand the role of a bibliographic specification;
  • define and configure a rendering;
  • distinguish record selection from record sorting;
  • use method=global , method=local , and method=dataset ;
  • use appropriate sorttype settings;
  • change the presentation without changing the bibliographic data;
  • compare different families of bibliographic style.

The guide also explains why terms such as APA, Chicago, MLA, Harvard, and Vancouver do not all describe the same kind of citation system.

In particular, it distinguishes:

  • author–date styles;
  • notes-and-bibliography styles;
  • author–page styles;
  • numerical styles;
  • project-specific or publisher-specific styles.

The exact specifications supplied with the current ConTeXt distribution, their names, and their scope are identified in that guide.

Read this guide if:

  • you can produce a bibliography but do not understand why particular records appear;
  • you confuse datasets and renderings;
  • changing sorttype does not change which records are selected;
  • you need to choose between APA, Chicago, a numerical system, or a custom editorial style;
  • you want to change the formatting without modifying the .bib database.

5.3. Guide 3 — Creating local and multiple bibliographies

Page: Creating local and multiple bibliographies

This guide deals with documents requiring more than one bibliography list.

It shows how to:

  • place a bibliography at the end of each chapter;
  • place a complete bibliography at the end of the document;
  • use several renderings with one shared dataset;
  • use several independent datasets;
  • distinguish primary sources from secondary literature;
  • cite records explicitly with dataset::key ;
  • reuse the same record key in different datasets;
  • decide between one shared collection and several independent collections;
  • allow a record to appear in both a local and a global bibliography.

Examples include the kinds of distinction commonly required in a work on the history of philosophy:

  • original works and historical editions;
  • translations;
  • secondary studies;
  • journal articles;
  • editorial and reference materials.

Read this guide if:

  • each chapter needs its own bibliography;
  • a final bibliography must repeat records already printed locally;
  • primary and secondary sources must remain separate;
  • several datasets contain similar or identical keys;
  • one list must contain all records while another contains only cited records.

5.4. Guide 4 — Organising bibliographies in complex editorial projects

Page: Organising bibliographies in complex editorial projects

This guide applies the bibliography subsystem to a structured book or scholarly edition.

It shows how to:

  • place bibliographic data in dedicated project directories;
  • load bibliographic settings from an environment;
  • keep chapter components independent of bibliography configuration;
  • define stable project-level citation and placement commands;
  • place bibliography components in the backmatter;
  • maintain separate primary and secondary datasets;
  • combine structured citations with references in editorial notes;
  • use \usecitation when a record must be selected without printing a visible citation;
  • diagnose duplicate keys, missing records, unsuitable categories, and incorrect relative paths;
  • centralise a project's bibliographic style and selection policy.

The examples are based on a simplified scholarly publishing project whose bibliographic databases are maintained with JabRef.

Read this guide if:

  • the document is divided into products, environments, and components;
  • bibliography commands are currently repeated in chapter files;
  • several output products must share the same bibliographic policy;
  • the bibliography forms part of a translation, critical edition, or long academic book;
  • manual references in notes must coexist with structured records.

7. Bibliographic styles

A bibliographic style governs more than punctuation.

Depending on the convention, it may determine:

  • whether citations use names, dates, page numbers, or numerical labels;
  • whether full references appear in notes or only in a final bibliography;
  • the order of given names and family names;
  • how several authors or editors are presented;
  • the treatment of titles, subtitles, editions, translations, and series;
  • the position of the publication year;
  • the use of quotation marks and italics;
  • the order of the bibliography list;
  • the treatment of repeated citations.

For example, the same work may be represented conceptually as:

Style family Typical citation form
Author–date (Beiser, 1987)
Chicago author–date (Beiser 1987, 42)
Author–page (Beiser 42)
Numerical [1]
Notes and bibliography A full or shortened reference in a note, with a bibliography entry

These forms are illustrative. The exact result depends on the active ConTeXt specification and its configuration.

A bibliographic database should therefore contain stable publication data rather than visual instructions tied to one style. Styles and project-specific adjustments belong in the ConTeXt configuration.

8. Bibliographic data sources

The most common source is a BibTeX-format .bib file.

ConTeXt can also load bibliographic data from:

  • a named buffer containing BibTeX records;
  • a Lua table;
  • an XML file;
  • some older bibliography formats.

For most manually maintained bibliographies, a .bib file remains the simplest and most portable solution.

Buffers are especially useful for minimal working examples because the data and the ConTeXt source can be copied as one file.

Lua and XML become useful when bibliographic records are generated or transformed as part of a larger automated workflow.

The older MkII bibliography system and its intermediate .bbl representation are documented separately at Bibliography mkii.

9. Scope of this collection

The guides concentrate on current ConTeXt MkIV and LMTX.

They cover:

  • structured bibliographic data;
  • citations in running text and notes;
  • bibliography lists;
  • selection and sorting;
  • bibliographic styles and specifications;
  • local and multiple bibliographies;
  • datasets and renderings;
  • structured editorial projects;
  • common errors and diagnostic methods.

They do not attempt to reproduce the complete publications manual or document every low-level BTX command.

Advanced command-level information belongs in the command reference and in the official manual.

12. What this page has established

Bibliographic work in ConTeXt is organised around a separation of responsibilities:

  • bibliographic sources store publication data;
  • datasets make those records available to ConTeXt;
  • specifications define bibliographic conventions;
  • citations retrieve and present individual records;
  • renderings select, sort, and format bibliography lists;
  • project environments centralise the rules used by larger publications.

The four guides develop these operations progressively:

  1. create records, citations, and a first bibliography;
  2. understand datasets, styles, renderings, selection, and sorting;
  3. produce local or multiple bibliographies;
  4. organise bibliographic work in a complex editorial project.
