Modern OpenType fonts can contain much more than a collection of glyphs. They may also contain instructions for selecting or positioning glyphs in particular contexts.

Examples include:

  • standard ligatures such as fi and fl ;
  • small capitals;
  • oldstyle or lining figures;
  • proportional or tabular figures;
  • discretionary ligatures;
  • stylistic alternates;
  • stylistic sets;
  • script- and language-specific substitutions.

ConTeXt can activate these OpenType features and combine them into named sets that can be applied globally or locally.

This page explains the distinction between an OpenType feature and a ConTeXt feature set, shows the basic commands used to control them, and provides a reference to common OpenType feature tags.

For general font selection and configuration, see Use any font you want.

1. OpenType feature and ConTeXt feature set

There are two related but distinct concepts.

OpenType feature
A capability provided by the font itself and identified by a standard tag such as liga , smcp , onum , or ss01 .
ConTeXt feature set
A named collection of one or more OpenType features, defined with \definefontfeature .

For example: 

  • \setupbodyfont[pagella]

\definefontfeature
  [myoldstyle]
  [onum=yes,
   lnum=no]

\starttext

Default figures: 1234567890

{\feature[+][myoldstyle]
Oldstyle figures: 1234567890}

\stoptext

Here:

  • onum and lnum are OpenType feature tags;
  • myoldstyle is the name of a ConTeXt feature set.

Important.

A ConTeXt feature set does not create capabilities that are absent from the font. For example, smcp=yes can activate real small capitals only if the font provides the corresponding OpenType feature and glyphs.

2. Defining a feature set

A feature set is defined with \definefontfeature.

For example: 

\definefontfeature
  [mysmallcaps]
  [smcp=yes]

A feature set may contain more than one OpenType feature: 

\definefontfeature
  [bookfigures]
  [onum=yes,
   pnum=yes]

This makes it possible to give a meaningful name to a typographical configuration and reuse it later.

3. Applying a feature locally

A defined feature set can be added locally with \feature. 

  • \setupbodyfont[pagella]

\definefontfeature
  [mysmallcaps]
  [smcp=yes]

\starttext

Normal text.

{\feature[+][mysmallcaps]
Text with the small-cap feature enabled.}

Normal text again.

\stoptext

The feature change is local when it is placed inside a group.

4. Combining several features

A feature set can contain several OpenType features: 

  • \setupbodyfont[pagella]

\definefontfeature
  [bookstyle]
  [onum=yes,
   lnum=no,
   pnum=yes]

\starttext

Default: 1234567890

{\feature[+][bookstyle]
Book style: 1234567890}

\stoptext

Several named feature sets may also be combined where appropriate. 

\feature[+][smallcaps,oldstyle]

Note.

The result depends on the features actually provided by the selected font. Not every OpenType font contains every feature listed on this page.

5. Modifying the active feature set

ConTeXt provides several commands for changing the current set of font features.

The following forms are equivalent ways of expressing the same operations:

Action Command \feature form Short form
Add \addfeature[f:mine] \feature[more][f:mine] \feature[+][f:mine]
Subtract \subtractfeature[f:mine] \feature[less][f:mine] \feature[-][f:mine]
Replace \replacefeature[f:mine] \feature[new][f:mine] \feature[=][f:mine]
Reset and add \resetandaddfeature[f:mine] \feature[local][f:mine] \feature[!][f:mine]
Restore \revivefeature[f:mine] \feature[old][f:mine] \feature[>]
Reset \resetfeature \feature[reset] \feature[<]

6. Script and language information

Some OpenType processing depends on the script or language for which a font is being used.

Older examples often contain definitions such as: 

\definefontfeature
  [example]
  [mode=node,
   script=latn,
   language=dflt,
   kern=yes,
   liga=yes]

The script and language keys describe the OpenType script and language system used while processing the font.

They should not be confused with ConTeXt document-language settings such as \mainlanguage or \language.

For the distinction between document language, script, font, and writing direction, see:

7. Inspecting and debugging OpenType processing

OpenType processing can become difficult to understand when several features, scripts, fallbacks, or substitutions interact.

One useful diagnostic command is \showotfcomposition.

For example: 

\showotfcomposition
  {mikhak-medium*arabic}
  {-1}
  {سلام علیکم}

The second argument can be used to indicate direction; the example above is for right-to-left text.

For general right-to-left and bidirectional typesetting, see the dedicated RTL/BiDi documentation.

A feature may also fail to behave as expected when some of the relevant glyphs come from a fallback font rather than from the font whose OpenType lookups are being applied.

8. Common OpenType feature tags

OpenType features are identified by four-character tags.

The following table lists some common examples.

These features are not guaranteed to exist in every font.

8.1 Ligatures and contextual forms

Feature Tag
Standard ligatures liga
Contextual alternates calt
Discretionary ligatures dlig

For more detailed control of ligatures, see Ligatures.

8.2 Letter forms

Feature Tag
Small capitals smcp
Capitals to small capitals c2sc
Swashes swsh
Stylistic alternates salt

8.3 Figures

Feature Tag
Lining figures lnum
Oldstyle figures onum
Proportional figures pnum
Tabular figures tnum
Fractions frac
Ordinals ordn

8.4 Stylistic sets

OpenType defines stylistic-set tags from:

ss01 through ss20.

A font may provide none, some, or all of these sets.

The visual meaning of a particular stylistic set is defined by the font designer and therefore varies from font to font.

9. Ligatures

Ligatures are one application of OpenType features.

Standard and discretionary ligatures are commonly controlled through features such as: 

liga=yes
dlig=yes

Detailed questions such as:

  • breaking a ligature at a particular position;
  • language-specific ligature suppression;
  • \noligature ;
  • word-replacement dictionaries;
  • \blockligatures ;

10. Advanced: adding OpenType behaviour

In advanced applications it is possible to add or modify OpenType behaviour beyond the ordinary activation of features already defined in a font.

Several mechanisms have been used in ConTeXt.

10.1 Lua-defined features

Low-level Lua interfaces can define additional OpenType features.

Older examples use functions such as:

font.handlers.otf.addfeature

This is an advanced mechanism and normally is not needed merely to activate an existing OpenType feature.

12. Troubleshooting

If an OpenType feature does not produce the expected result, check the following points.

Does the font actually provide the feature?
Not every font contains small caps, oldstyle figures, stylistic sets, discretionary ligatures, or other optional features.
Are the required glyphs in the same font?
Some OpenType lookups depend on glyphs belonging to the font whose feature processing is active. Fallback fonts can therefore affect the result.
Is the correct script being processed?
Some OpenType features are script-specific.
Is the language relevant?
Certain fonts contain language-specific substitutions.
Is another feature overriding the requested feature?
For example, lining and oldstyle figure settings may interact.
Is the example inherited from an older MkIV setup?
Historical recipes may contain settings that are unnecessary or no longer recommended in current LMTX.

For general font problems, see Use any font you want.
